### Fixed

- Ranged downloads mark their staging payload sparse before sizing it, removing the disk-speed zero-fill window on Windows; filesystems without sparse support keep the previous behaviour. (#212)

On NTFS the file size is set immediately while the valid-data length stays at zero, so the first ranged write beyond that point zero-filled the gap at disk speed: 8 GB at 100 MB/s took about 80 s, and 50 GB at 500 MB/s about 100 s. The staging payload is now marked sparse before it is sized, and filesystems without sparse support keep the previous behaviour.

### Changed

- Repository Details uses a two-line identity and **This copy** facts header, opens the repository from its title, keeps whole-copy deletion fixed above the footer with a target path, and moves location choice into the contents heading; dataset and shard counts appear once. (#213)

The dialog now has a two-line header, its title is clickable and opens the repository, and location choice is a single select in the contents heading. The whole-copy delete block stays fixed above the footer, and the dataset and shard counts are de-duplicated.
