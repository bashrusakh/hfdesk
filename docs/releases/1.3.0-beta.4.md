### Added

- GGUF quantization recognition now includes the two PrismML ternary packings **PTQ1_0** (dense trit packing, 1.75 bits/weight) and **PQ2_0** (one trit per 2-bit slot, 2.13 bits/weight): repositories such as `prism-ml/Ternary-Bonsai-2-27B-gguf` show labelled quantization rows instead of `Unknown`, both descriptions state that they require the PrismML llama.cpp fork because mainline llama.cpp, Ollama and LM Studio cannot load them, and neither type is ever auto-recommended — the ordinary recommendation rules and the smallest-RAM budget fallback skip them, while both remain selectable explicitly. Exact tokens only: the standard `Q2_0` token still parses as before, and extended or prefix-variant spellings stay unclassified.

### Fixed

- A large ranged download no longer shows a silent 0 B/s window while its staging file is created and preallocated: the downloader emits `file_preparing` before the first transfer byte, the job exposes `phase: "preparing"`, and network speed/ETA stay at zero until transfer progress resumes — the same treatment `file_finalizing` already gives the post-transfer stage.
- Whole-folder deletion now treats every recognized mmproj companion spelling as part of its model instead of a separate model: a leading `mmproj-`, a `.mmproj-` or `-mmproj-` delimiter after a model part, and exactly `mmproj.gguf` contribute no model key, case-insensitively and with any token after `mmproj-`, so a folder with one model's weights and any number of projector files (for example `Omnicoder-9B-Opus-Distill.q8_0.gguf` with `mmproj-F32.gguf` and `mmproj-F16.gguf`) is whole-folder deletable. A folder containing only companions still has no recognized model weight and stays refused. The cache-metadata/selection `mmproj` substring rule is unchanged.

- A GGUF `vision_encoder` (mmproj) row is no longer marked recommended on its own: in a repository with LLM quantization artifacts the preferred projector is recommended only together with a recommended quantization, so the `★ rec` badge and `recommended_download` never point at a lone mmproj file — when no quantization meets the existing recommendation rule, nothing is recommended and `recommended_download` is absent. An mmproj-only repository still recommends its preferred projector, and a RAM-budget re-pick applies the same rule: a projector cannot stay recommended without a recommended quant, and when the budget picks a quant its projector is bundled again. The quantization recommendation rule, per-row download controls, and the badge rendering are unchanged.

- Model Details keeps **Overview** as the default tab for every recognized repository, including a plain Transformers base model whose analysis offers no selectable items; only an unrecognized/generic repository opens on **Files**, whose tree is its only download path. Navigation to a lineage or related repository therefore lands on the description instead of the file picker.

- A Community discussion link to a repository root on the configured Hub endpoint (`/<owner>/<repo>` or `/datasets/<owner>/<repo>`) now opens that repository in Model Details instead of leaving the app for the browser. Blob, tree, resolve and commit URLs, reserved Hub pages, links on another host, and `mailto:` or other non-http(s) links keep their external behavior, and the sanitized comment HTML is unchanged.
