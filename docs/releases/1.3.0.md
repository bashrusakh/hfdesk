# HFDesk 1.3.0

First stable release after 1.2.2. It adds service mode — HFDesk running as a supervised background service — and a Windows desktop app with a tray companion and one Logs window, on top of the existing search, download, cache and mirror features.

### Changed

- The tray and the Logs window show one line of service state (`Service: not installed` … `Service: running` … `Service: failed`), and the window carries the same actions as a single `Service ▾` control.
- One Logs window uses a single frame: the live log while the address answers, and the same frame with a retry, log-file actions and the log tail when it does not.
- Updating a running service asks first and states that it is stopped and started again with running downloads interrupted; deleting states that a running service is stopped first and removes only the registration, keeping data, cache, config, history and logs.
- Docker keeps all writable state — settings, jobs, history, HF cache and local models — under one `/data` root by default.
- The build toolchain is Go 1.26.

### Fixed

- The Logs window follows the service while it stays open: a service that stops, fails or loses its registration redraws it, and returning focus re-reads the state.
- Installing from the desktop app no longer flashes a red error in the Logs window.
- The service log under `%ProgramData%` is readable from the Logs window: each start grants interactive users read access to the instance's own log directory and active log file.

### Updating

- Docker: move the persisted volume to `/data`; otherwise settings, jobs/history, the HF cache and local models are not persisted.
- Building from source requires Go 1.26 (`go.mod`).

### Known limitations

- On macOS, a process crash can leave a temporary pin directory that HFDesk does not remove.
- External filesystem changes are not excluded atomically between the final identity check and deletion.

### Verification

- CI runs on Linux, Windows and macOS, plus the release workflow. Windows smoke (install, Logs window, tray, service actions) was run by the owner.
