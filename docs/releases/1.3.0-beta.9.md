### Changed

- The Windows desktop host's missing console program notice — at the install precheck and before either update entry reaches the administrator prompt — is a task dialog: the missing file as its bold line, the folder under it, a **Download it and continue** command link that fetches exactly that program of this release behind a progress dialog with **Cancel** and verifies its SHA-256 before placing it, with the note line naming the action it continues — then the same service action continues through its usual confirmation and administrator prompt — a **Not now** answer, and the manual steps in a collapsed **Install it manually instead** expander; a start runs the registered program and never sees the notice, a local build without a version and a release without an authoritative checksum are never offered a download, and a failed or cancelled transfer leaves no file of its own, never touching a file it did not place. (#219)

The download is fail-closed: the host takes the release's `checksums.txt` as the authoritative checksum source, and with no such source — a local build without a version, or a release without a checksum asset — no download is offered and no file appears. The SHA-256 is verified before the file is placed; a mismatch, a failed transfer or a cancelled transfer leaves no file of its own and never touches a file this action did not place. Once the program is in place, the service action continues through its usual confirmation and administrator prompt, and the manual steps stay available in the collapsed expander.

- The Windows desktop host shows whether the Windows service is installed on both of its surfaces. The tray menu starts with a status line — `Service: installed (running)`, `Service: not installed`, or `Service: unknown` when the state could not be read, which never claims a machine without a service — re-read after the host's service actions and every 30 seconds; with a service installed, **Install service…** stays visible but greyed beside a new **Service…** item that opens the same registered-service dialog (open, start or update), and without one **Install service…** is the active item with no dead second item beside it. The Runtime / Logs window shows the same status as a header chip and adds an **Install service…** button that is enabled only while no service is installed and runs the exact tray installation flow; the host's single-action guard refuses a second installation while one is in flight, whichever surface started it. (#219)

The tray line is re-read after the host's service actions and on a 30-second refresh (`trayServiceRefreshInterval`), so it reports the registered state rather than a cached one, and `Service: unknown` is used whenever the state could not be read — never a claim that the machine has no service. With a service installed, the tray greys **Install service…** beside the new **Service…** item, which opens the same registered-service dialog (open, start or update); without one, **Install service…** is the active item. The Runtime / Logs window mirrors this as a header chip and a button that is enabled only while no service is installed, and both surfaces run the single guarded installation flow, so a second installation is refused while one is in flight, whichever surface started it.

- Cancelling a download (or cleaning a paused job's leftover part files) in local-folder mode now removes the directories its removed partials leave completely empty, up to the output root; any directory that still holds content, the output root itself, and the HF cache layout are untouched. (#218)

In flat output mode, explicit-cancel cleanup and `CleanupJobPartFiles` walk the removed partial's directory chain upward while each directory is completely empty, stopping at the first directory that still holds content, is a symlink or non-directory, leaves the output root, or is held by a live writer; the output root itself and the HF cache layout are never pruned. Each removal takes the directory's tree-removal admission after the destination scope is released, so a concurrent writer is never disrupted, and pause and internal abort keep preserving resumable partials without pruning.
