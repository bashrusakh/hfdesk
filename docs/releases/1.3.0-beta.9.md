### Changed

- The Windows desktop host's missing console notice can download the paired console program and continue the service action (#219).

When the console program is missing — at the install pre-check, and just before either update route reaches the administrator prompt — you get a dialog whose first line names the missing file and shows the folder it belongs in. It offers **Download it and continue**: that fetches exactly this release's copy of the program behind a small progress window with **Cancel**, checks it against the release's published checksum before putting it in place, and then carries on with the action it was started for. There is also **Not now**, plus the manual steps under **Install it manually instead**. The download is careful about failures: the release's checksums.txt is the only trusted checksum source, so a local build with no version, or a release published without a checksum file, gets no offer and no file at all, and a wrong checksum, a failed transfer or a cancelled download leaves nothing of its own behind — when anything goes wrong, nothing in your folder is lost or overwritten. Once the program is in place, the service action continues through its usual confirmation and administrator prompt.

- The Windows desktop host shows the service registration state on both of its surfaces, with the install-service actions sharing one flow (#219).

The tray menu now opens with a status line — Service: installed (running), Service: not installed, or Service: unknown when the state could not be read, in which case it never claims a machine has a service it cannot actually see. That line is refreshed after every service action and kept up to date while the app runs, so it reports what is really on the machine rather than an old answer. With a service installed, **Install service…** stays visible but greyed out, next to a new **Service…** entry that opens the usual dialog for the registered service (open, start or update); without one, **Install service…** is the active entry and there is no dead second item beside it. The Runtime / Logs window shows the same status at the top of the window and adds its own **Install service…** button, which is enabled only while no service is installed and runs exactly the same installation as the tray. If an installation is already under way, a second one is refused whichever surface you start it from. The window's install-service action reaches the host over the app's own local interface, and both surfaces read the same state, so the window and the tray cannot drift apart.

- Cancelling a download (or cleaning a paused job's leftover part files) in local-folder mode now removes the directories its removed partials leave completely empty, up to the output root (#218).

When you cancel a download in local-folder mode, or clean up the leftover part files of a paused job, any folder that the removed partial files leave completely empty is removed as well — walking upward from the removed files toward the output root and stopping at the first folder that still holds anything, is not a plain folder (a link, say), sits outside the output root, or is in use by another running transfer.

(Note: this text intentionally says Service: installed (running) — that is what the published beta.9 artifacts actually ship; the presence-only wording landed after the release and stays in Unreleased.)
